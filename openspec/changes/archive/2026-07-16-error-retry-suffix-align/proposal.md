# error-retry-suffix-align

## Why

에러 안내 카피 전수 조사(13곳) 결과 서비스 지배 관례는 재시도 접미 없는 사실 서술형("…에 실패했습니다") 10곳이다. 그런데 핀 상세 "보드에 추가" 모달 안에서 보드 추가 실패(재시도 접미 있음)와 보드 생성 실패(접미 없음)가 동일 컴포넌트·동일 모달·동일 피드백 채널·동일 재시도가능 실패 범주인데도 문형이 갈린다. 층위/역할/채널 어느 경계로도 설명되지 않는 갈림이므로 지배 관례로 정렬한다.

## What Changes

- 보드 추가 실패 안내 문구에서 재시도 유도 접미(". 다시 시도해주세요")를 제거하여 무접미 사실 서술형("보드 추가에 실패했습니다")으로 정렬
- 중복 추가 안내(409), 보드 생성 실패 안내, 로그인 페이지 에러 카피(페이지 층위 경계로 스코프 외)는 변경 없음

## Capabilities

### New Capabilities

(없음)

### Modified Capabilities

- `board`: "보드 핀 추가 실패 피드백은 서비스 공통 실패 안내 문형을 따른다" 요구사항에서 재시도 안내 제공 의무(SHALL)를 제거 — 동일 피드백 영역의 다른 실패 안내와 문형이 일치해야 한다는 요구로 대체

## Impact

- `apps/web/src/components/board/AddToBoardButton.tsx` 실패 안내 문자열 1건
- API/백엔드/의존성 영향 없음
