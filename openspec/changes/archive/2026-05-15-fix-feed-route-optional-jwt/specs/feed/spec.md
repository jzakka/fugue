## ADDED Requirements

### Requirement: 피드 라우트는 선택적 인증 미들웨어로 보호된다

production 서버 라우터의 피드 엔드포인트는 선택적 인증 미들웨어를 통해 핸들러에 도달해야 한다(SHALL). 인증 토큰이 존재하면 그 토큰의 유저 식별자가 핸들러에 노출되어야 한다(SHALL). 토큰이 부재하거나 유효하지 않으면 핸들러가 비인증 호출자에 대한 분기를 수행하도록 빈 인증 컨텍스트로 진입해야 한다(SHALL). 피드 라우트가 토큰 부재만으로 401을 반환해서는 안 된다(SHALL NOT).

본 Requirement는 기존 Requirement `개인화된 추천 피드를 제공한다`가 production에서 enforce되도록 보장하는 wiring 계약이다. 기존 Requirement의 행위 정의(보유 핀 수에 따른 개인화·콜드스타트·비인증 분기)는 변경하지 않는다.

#### Scenario: 인증 토큰을 가진 피드 요청

- **WHEN** 인증 토큰을 제시한 호출자가 피드를 요청하면
- **THEN** 핸들러는 호출자의 유저 식별자로 분기 가능한 상태에서 호출되어, 기존 Requirement `개인화된 추천 피드를 제공한다`의 "충분한 핀이 있는 유저"·"핀이 부족한 유저(콜드 스타트)" Scenario에 정의된 응답을 반환한다

#### Scenario: 인증 토큰 없는 피드 요청

- **WHEN** 인증 토큰이 없는 호출자가 피드를 요청하면
- **THEN** 핸들러는 비인증 분기를 수행하며, 기존 Requirement `개인화된 추천 피드를 제공한다`의 "비인증 유저" Scenario에 정의된 응답을 반환한다. 401은 반환되지 않는다

#### Scenario: 유효하지 않은 토큰을 가진 피드 요청

- **WHEN** 만료·서명 불일치·식별자 파싱 실패 중 어느 사유로든 유효하지 않은 토큰을 제시한 호출자가 피드를 요청하면
- **THEN** 핸들러는 비인증 분기를 수행하며, "비인증 유저" Scenario에 정의된 응답을 반환한다. 401은 반환되지 않는다
