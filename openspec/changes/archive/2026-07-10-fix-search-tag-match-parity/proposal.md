# fix-search-tag-match-parity — Proposal

## Why

통합 검색(`GET /api/search`)에서 검색어 길이에 따라 태그 매칭 규칙이 달라진다. 검색어가 2자 이하이면 태그가 대소문자 구분 없이 부분 일치로 검색되지만, 3자 이상이 되는 순간 태그 매칭이 대소문자를 구분하는 완전 일치로 후퇴한다. 그 결과 사용자가 `art`로 좁혀 검색하면 `Art` 태그가 붙은 핀이 결과에서 사라지는 등, 검색어를 더 구체적으로 입력할수록 오히려 결과가 줄어드는 직관에 반하는 동작이 발생한다.

## What Changes

- 3자 이상 검색어 경로(유사도 검색 경로)의 태그 매칭을 2자 이하 경로와 동일한 의미(대소문자 무시 부분 일치)로 통일한다.
- 태그 매칭으로 인한 검색 결과 포함 여부와 태그 일치 가산점 부여 기준이 두 경로에서 같은 매칭 규칙을 따르게 된다.
- 검색어 길이와 무관하게 태그 매칭 의미가 일관됨을 고정하는 테스트를 추가한다.

## Capabilities

### New Capabilities

- `search`: 통합 검색의 태그 매칭 일관성. 검색어 길이에 따른 검색 경로 전환과 무관하게, 태그 매칭은 항상 대소문자를 구분하지 않는 부분 일치 의미를 유지한다는 행위 계약을 정의한다.

### Modified Capabilities

(없음 — `openspec/specs/`에 search 스펙이 아직 존재하지 않는다.)

## Impact

- 핀 검색 SQL 쿼리 (유사도 경로의 태그 매칭 조건 및 태그 일치 가산점 조건)
- 검색 핸들러의 핀 검색 경로 (외부 동작 변화: 3자 이상 검색어에서 태그 매칭 결과가 늘어남)
- Linear 이슈: NAV-1248
- API 계약(요청/응답 형태) 변경 없음, DB 스키마 변경 없음
