## ADDED Requirements

### Requirement: 개인화 피드의 페이지네이션은 페이지 간 작품 중복을 반환하지 않는다

시스템은 개인화 피드(authenticated 호출자 + 보유 핀 수가 콜드스타트 임계 이상) 분기에서 응답된 `next_cursor`를 그대로 다음 요청에 전달했을 때, 다음 페이지의 응답이 이전 페이지에 포함되었던 작품을 포함해서는 안 된다(SHALL NOT). 즉 연속한 두 페이지 응답의 작품 식별자 교집합은 비어 있어야 한다(SHALL).

개인화 분기는 추천 후보(태그 매칭·미디어 타입 매칭)와 최신 작품 보충 두 종류의 소스에서 작품을 모아 응답을 만든다. cursor가 표현하는 페이지 위치(offset)는 응답을 만들 때 사용되는 모든 underlying 쿼리에 일관되게 전파되어야 한다(SHALL). 어떤 underlying 쿼리도 페이지 위치를 무시한 채 첫 페이지의 결과를 그대로 다시 만들어내서는 안 된다(SHALL NOT).

본 Requirement는 기존 Requirement `개인화된 추천 피드를 제공한다` Scenario "피드 페이지네이션"의 SHALL("이전 페이지에 포함되지 않은 작품이 반환된다")이 production에서 enforce되도록 보장하는 wiring 계약이다. 기존 Scenario의 의미와 cold-start/비인증 분기의 동작은 변경하지 않는다.

#### Scenario: 연속한 두 페이지의 작품 ID 교집합은 비어 있다

- **WHEN** 보유 핀 수가 콜드스타트 임계 이상인 인증된 호출자가 첫 페이지 피드를 요청하고, 응답의 `next_cursor`를 그대로 두 번째 요청의 cursor로 전달하면
- **THEN** 두 응답의 `pins[].id` 집합은 disjoint이다. 같은 작품이 두 페이지에 모두 등장해서는 안 된다

#### Scenario: 페이지 offset이 모든 underlying 소스에 일관되게 적용된다

- **WHEN** 개인화 분기로 두 번째 페이지가 만들어지면
- **THEN** 응답 페이로드를 구성하는 모든 underlying 쿼리(태그 기반 추천·미디어 타입 기반 추천·최신 작품 보충 등 응답을 만드는 데 사용되는 모든 소스)는 첫 페이지가 소비한 위치 다음에서부터 작품을 가져온다. 어떤 소스도 첫 페이지와 동일한 결과를 반환하지 않는다

#### Scenario: cold-start와 비인증 분기에는 추가 제약을 부과하지 않는다

- **WHEN** 보유 핀 수가 콜드스타트 임계 미만인 인증된 호출자 또는 비인증 호출자가 페이지 피드를 요청하면
- **THEN** 응답은 기존 Requirement `개인화된 추천 피드를 제공한다`의 "핀이 부족한 유저(콜드 스타트)"·"비인증 유저" Scenario가 정의한 동작을 따른다. 본 Requirement는 이들 분기에 대해 추가 제약을 부과하지 않는다
