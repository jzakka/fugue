## Context

현재 핀 생성 플로우에서 태그는 3개 레이어에서 필수로 강제되고 있다:
1. **Frontend** (`PinCreateForm.tsx`): `selectedTagIds.size === 0`이면 에러 표시
2. **API** (`pin/handler.go`): 태그 ID 배열이 비어있으면 400 응답 + 핀 롤백
3. **Spec** (`pin/spec.md`): "태그가 없거나 10개를 초과하면 오류"

DB 스키마(pin_tags N:M)는 이미 0개를 허용하므로 마이그레이션 불필요.

## Goals / Non-Goals

**Goals:**
- 핀 생성 시 태그 0개 허용 (최대 10개 제한 유지)
- 프론트엔드/API 양쪽의 유효성 검사 일관성 유지

**Non-Goals:**
- 태그 없는 핀에 대한 자동 태깅 시스템 (향후 별도 변경)
- 피드/검색에서 태그 없는 핀의 노출 로직 변경 (기존 로직 그대로)
- 기존 핀의 태그 제거 기능 (핀 수정은 현재 미구현)

## Decisions

### 1. 유효성 검사 범위를 0~10으로 변경

태그 배열의 유효 범위를 `1 ≤ len ≤ 10`에서 `0 ≤ len ≤ 10`으로 변경한다.

- **API**: 빈 태그 배열 허용. `tag_ids` 필드 자체가 없거나 빈 배열이면 태그 연결 단계를 스킵.
- **Frontend**: 태그 0개 에러 메시지 제거, 필수 표시(*) 제거. 태그 섹션 UI는 그대로 유지하되 "선택사항"으로 안내.

### 2. API 요청 포맷 변경 없음

`tag_ids` 필드는 기존과 동일하게 배열로 받되, 빈 배열 `[]`도 허용. 필드 생략 시에도 빈 배열과 동일하게 처리.

## Risks / Trade-offs

- **[태그 없는 핀의 검색 노출 저하]** → 피드는 최신순 정렬이 기본이므로 즉각적 문제 없음. 태그 기반 필터에서는 노출되지 않지만, 이는 사용자가 태그를 선택하지 않은 의도적 결과. 향후 자동 태깅으로 보완 가능.
- **[업로드 품질 저하 가능]** → 태그 없는 핀이 늘어나면 전체 콘텐츠 분류 품질이 떨어질 수 있음. 하지만 MVP 단계에서 업로드 허들을 낮추는 것이 더 중요.
