## MODIFIED Requirements

### Requirement: 스크립트를 검증한다
시스템은 스크립트 실행 결과를 검증하여 최소 품질 기준을 만족하는지 확인해야 한다.

#### Scenario: 검증 통과 - 최소 아이템 수 충족
- **WHEN** 스크립트가 최소 10개의 유효한 아이템을 추출할 때
- **THEN** 검증이 통과한다

#### Scenario: 검증 실패 - 아이템 수 부족
- **WHEN** 스크립트가 10개 미만의 유효한 아이템을 추출할 때
- **THEN** 검증이 실패하고 "유효 아이템 N개 (최소 10개 필요)" 메시지를 반환한다

#### Scenario: 필수 필드 검증
- **WHEN** 추출된 아이템들을 검증할 때
- **THEN** 각 아이템이 미디어 URL과 소스 URL 필드를 모두 가지고 있는지 확인한다
- **AND** 두 필드 중 하나라도 비어있으면 해당 아이템은 유효하지 않은 것으로 간주한다

#### Scenario: 선택적 필드는 검증하지 않음
- **WHEN** 아이템에 제목 필드가 비어있을 때
- **THEN** 미디어 URL과 소스 URL이 존재하면 여전히 유효한 아이템으로 간주한다

#### Scenario: 스크립트 실행 오류 처리
- **WHEN** 스크립트 실행 중 런타임 오류가 발생할 때
- **THEN** 검증이 실패하고 오류 메시지를 포함한 결과를 반환한다
- **AND** 유효 아이템 수를 0으로 설정한다

#### Scenario: 검증 결과 구조화
- **WHEN** 검증이 완료될 때
- **THEN** 성공 여부, 총 아이템 수, 유효 아이템 수, 오류 메시지를 포함한 구조화된 결과를 반환한다

## ADDED Requirements

### Requirement: 명확한 검증 기준을 적용한다
시스템은 일관되고 측정 가능한 검증 기준을 사용해야 한다.

#### Scenario: 최소 임계값 설정
- **WHEN** 검증을 수행할 때
- **THEN** 최소 10개의 유효 아이템을 요구한다

#### Scenario: 부분 성공 거부
- **WHEN** 스크립트가 일부 아이템만 올바르게 추출할 때 (예: 20개 중 5개만 유효)
- **THEN** 유효 아이템 수가 최소 기준 미만이면 검증이 실패한다

#### Scenario: JSON 파싱 우선 유도
- **WHEN** DOM 스크래핑으로 5-15개 추출 vs JSON 파싱으로 50+ 개 추출
- **THEN** 최소 10개 기준이 JSON 파싱 방식을 선호하도록 유도한다
