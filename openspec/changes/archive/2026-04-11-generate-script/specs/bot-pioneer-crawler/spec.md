## MODIFIED Requirements

### Requirement: AI로 파싱 스크립트를 생성한다
시스템은 페이지 HTML과 URL을 AI에 전달하여 파싱 스크립트를 생성해야 한다. 실패 시 피드백과 함께 재생성을 반복한다.

#### Scenario: 새 노드 타입용 스크립트 생성
- **WHEN** 특정 (사이트, 노드타입) 조합에 대한 스크립트가 없을 때
- **THEN** AI를 호출하여 스크립트를 생성한다

#### Scenario: 첫 시도에서 성공
- **WHEN** 생성된 스크립트가 첫 실행에서 검증을 통과할 때
- **THEN** 스크립트를 즉시 반환하고 추가 반복 없이 완료한다

#### Scenario: 검증 실패 시 재생성
- **WHEN** 생성된 스크립트가 검증에 실패할 때 (아이템 수 부족 또는 필수 필드 누락)
- **THEN** 실패 사유를 포함한 피드백과 함께 AI에 재생성을 요청한다

#### Scenario: 최대 반복 횟수 소진
- **WHEN** 모든 반복에서 검증이 실패할 때
- **THEN** 모든 시도 중 가장 많은 유효 아이템을 추출한 스크립트를 선택한다
- **AND** 선택된 스크립트가 0개를 추출했다면 오류를 반환한다

#### Scenario: AI에 피드백 제공
- **WHEN** N번째 반복이 실패했을 때
- **THEN** N+1번째 프롬프트에 실패 사유(추출된 아이템 수, 유효 아이템 수, 오류 메시지)를 포함한다
- **AND** 실패한 스크립트의 참조 정보를 함께 제공한다

## ADDED Requirements

### Requirement: 일반화된 프롬프트를 사용한다
시스템은 사이트별 하드코딩 없이 추출 전략을 기술하는 프롬프트를 사용해야 한다.

#### Scenario: 다양한 콘텐츠 타입에 동일 프롬프트 적용
- **WHEN** 아트 사이트(Pixiv)와 음악 사이트(SoundCloud)에 스크립트를 생성할 때
- **THEN** 동일한 기본 프롬프트 구조를 사용하되 사이트별 셀렉터는 포함하지 않는다

#### Scenario: 전략 우선순위 제시
- **WHEN** 프롬프트를 생성할 때
- **THEN** "JSON 파싱 우선, DOM 스크래핑은 폴백"과 같은 전략을 기술한다
- **AND** 구체적인 CSS 셀렉터나 XPath는 포함하지 않는다

### Requirement: 실패한 스크립트를 디버깅 가능하게 저장한다
시스템은 검증에 실패한 스크립트를 개발자가 검토할 수 있도록 보존해야 한다.

#### Scenario: 실패 스크립트 보존
- **WHEN** 반복 N에서 검증이 실패할 때
- **THEN** 스크립트 코드를 반복 번호와 도메인 정보와 함께 저장한다
- **AND** 저장된 스크립트는 개발자가 읽고 디버깅할 수 있어야 한다

#### Scenario: 실패 정보 추적
- **WHEN** 스크립트를 저장할 때
- **THEN** 어느 반복에서 실패했는지, 어떤 도메인인지 식별 가능한 정보를 포함한다
