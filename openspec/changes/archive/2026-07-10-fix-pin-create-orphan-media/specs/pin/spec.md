# pin — Delta Spec (fix-pin-create-orphan-media)

## ADDED Requirements

### Requirement: 핀 생성 실패 시 업로드된 미디어를 보상 삭제한다
핀 생성(`POST /api/pins`)에서 요청 입력에 대한 검증은 미디어를 저장소에 기록하기 전에 완료되어야 하며(SHALL), 검증 실패로 거절되는 요청은 저장소에 아무 객체도 생성하지 않아야 한다(SHALL NOT). 미디어 업로드 이후 단계가 실패하여 핀 생성 전체가 실패하면, 해당 요청으로 업로드된 모든 미디어 객체의 삭제를 시도해야 한다(SHALL). 보상 삭제 자체가 실패하는 경우의 처리는 별도 요구사항("보상 삭제 실패는 요청 결과와 독립적으로 기록된다")을 따른다.

#### Scenario: 폼 필드 검증 실패 시 저장소에 객체가 생성되지 않음
- **WHEN** 사용자가 유효한 미디어 파일과 함께 검증에 실패하는 폼 필드(예: 길이 제한을 초과하는 설명)를 보내 핀 생성이 거절되면
- **THEN** 저장소에는 해당 요청으로 인한 어떤 미디어 객체도 생성되지 않는다

#### Scenario: 핀 기록 실패 시 업로드된 미디어가 보상 삭제됨
- **WHEN** 미디어 업로드는 성공했으나 핀 데이터 기록이 실패하여 핀 생성이 실패하면
- **THEN** 이미 업로드된 미디어 객체는 저장소에서 삭제된다

#### Scenario: 태그 연결 실패 시 업로드된 미디어가 보상 삭제됨
- **WHEN** 미디어 업로드와 핀 기록은 성공했으나 태그 연결 실패로 핀 생성 전체가 실패 처리되면
- **THEN** 핀 데이터가 되돌려지는 것과 함께, 이미 업로드된 미디어 객체도 저장소에서 삭제된다

#### Scenario: 썸네일도 동일하게 보상 삭제됨
- **WHEN** 비디오 핀 생성에서 미디어와 썸네일이 모두 업로드된 뒤 이후 단계가 실패하면
- **THEN** 미디어 객체와 썸네일 객체가 모두 저장소에서 삭제된다

### Requirement: 보상 삭제 실패는 요청 결과와 독립적으로 기록된다
업로드된 미디어의 보상 삭제가 실패하더라도 핀 생성 요청의 실패 응답은 달라지지 않아야 하며(SHALL), 남겨진 orphan 객체를 운영자가 식별할 수 있는 기록을 남겨야 한다(SHALL).

#### Scenario: 보상 삭제 실패가 기록에 남음
- **WHEN** 핀 생성 실패 후 수행한 미디어 보상 삭제가 저장소 오류로 실패하면
- **THEN** 사용자는 원래의 실패 응답을 그대로 받고, 남은 객체를 식별할 수 있는 기록(객체 식별자 포함)이 남는다
