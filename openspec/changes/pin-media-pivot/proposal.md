## Why

현재 핀 생성 모델은 외부 URL을 필수로 입력하고 OG 메타데이터를 가져오는 방식이지만, Fugue의 핵심 가치인 "크로스미디어 큐레이션"을 제대로 전달하지 못한다. Pinterest처럼 미디어 파일(이미지/음원/비디오)을 핀의 본체로 삼고, URL은 원본 출처 참조로 두는 모델이 사용자 경험과 제품 정체성에 더 부합한다. 또한 자유 입력 태그는 오타, 중복, 비일관성 문제가 있으며, 사전 정의된 태그 시스템으로 전환해야 추천 품질과 탐색 경험을 높일 수 있다.

## What Changes

- **BREAKING** 핀 생성 시 미디어 파일(이미지/음원/비디오 중 하나) 업로드 필수
- **BREAKING** `url` 필드를 필수에서 선택으로 변경 (원본 출처 링크 용도)
- **BREAKING** `field` (분야) 필드 제거 — 미디어 타입과 태그가 분류 역할을 대체
- **BREAKING** 자유 입력 태그를 사전 정의된 태그 시스템으로 교체
- 파일 스토리지 인프라 추가 (S3/MinIO)
- 메인 화면 버튼 문구 "작품올리기" → "핀 생성"으로 변경
- 피드/추천 로직에서 분야 기반 → 태그/미디어타입 기반으로 전환

## Capabilities

### New Capabilities
(없음 — 모든 변경은 기존 도메인 범위 내)

### Modified Capabilities
- `pin`: 핀 생성 모델 변경 — 미디어 업로드 필수, URL 선택, 분야 제거, 사전 정의 태그 시스템 도입, MIME 타입 자동 감지
- `feed`: 추천 로직에서 분야(field) 기반 제거, 태그/미디어타입 기반 추천으로 변경

## Impact

- **DB**: `pins` 테이블에 `media_url`, `media_type` 컬럼 추가. `field` 컬럼 제거. `tags` 테이블 신설.
- **API**: 핀 생성 엔드포인트를 multipart 업로드로 변경. 태그 목록 조회 엔드포인트 추가.
- **프론트엔드**: 핀 생성 폼 전면 재설계 (파일 업로드 UI, 태그 선택 UI). PinCard에 미디어타입별 프리뷰.
- **인프라**: S3 버킷 + IAM 설정 (prod), MinIO 컨테이너 (dev docker-compose).
- **시드 데이터**: 사전 정의 태그 시드 (수백 개), 기존 핀 시드 데이터 마이그레이션.
