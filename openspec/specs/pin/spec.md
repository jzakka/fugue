## Purpose

핀(Pin)은 Fugue에서 사용자가 큐레이션·업로드하는 작품 단위다. 본 capability는 미디어 파일(이미지·오디오·비디오) 업로드와 그에 따른 클라이언트·서버 양측의 검증·변환·저장, 그리고 업로드된 핀의 조회·관련 핀 추천을 정의한다.
## Requirements
### Requirement: 미디어 파일을 업로드한다
시스템은 이미지, 음원, 비디오 파일을 업로드하고 저장할 수 있어야 한다(SHALL). 업로드 전에 클라이언트에서 파일 검증과 최적화를 수행한다(SHALL).

#### Scenario: 이미지 업로드 성공
- **WHEN** 인증된 유저가 이미지 파일을 업로드하면
- **THEN** 최적화된 이미지가 스토리지에 저장되고, 접근 가능한 URL이 반환된다

#### Scenario: 오디오 업로드 성공
- **WHEN** 인증된 유저가 오디오 파일을 업로드하면
- **THEN** 정규화된 오디오가 스토리지에 저장되고, 접근 가능한 URL이 반환된다

#### Scenario: 비디오 업로드 성공
- **WHEN** 인증된 유저가 비디오 파일을 업로드하면
- **THEN** 최적화된 비디오가 스토리지에 저장되고, 접근 가능한 URL이 반환된다

#### Scenario: 허용되지 않은 파일 형식
- **WHEN** 허용 목록에 없는 파일 형식을 선택하면
- **THEN** 서버 전송 없이 즉시 유효성 검사 오류가 표시된다

#### Scenario: 최적화 후에도 서버 크기 제한 초과
- **WHEN** 최적화 후에도 서버 제한을 초과하면
- **THEN** 크기 초과 오류가 표시되고 서버 전송이 차단된다

#### Scenario: 서버에서 크기 초과가 감지된 경우
- **WHEN** 클라이언트 검증을 통과했지만 서버에서 크기 제한 초과가 감지되면
- **THEN** 서버가 파일 크기 초과 오류를 반환한다 (이중 검증 체계의 서버 방어선)

#### Scenario: 서버가 본문을 디스크에 스풀하기 전에 본문 상한으로 거절한다
- **WHEN** 클라이언트 검증을 우회한 요청이 핀 생성 라우트의 본문 상한을 초과하는 multipart 본문을 전송하면
- **THEN** 서버는 multipart 파서가 본문을 디스크에 스풀하기 전에 본문 읽기를 중단하고, 파일 크기 초과 오류를 반환한다 (이중 검증 체계의 서버 방어선이 디스크 자원을 소모하기 전에 발동한다)

#### Scenario: 파일 업로드 영역에 허용 정보 안내
- **WHEN** 사용자가 핀 생성 폼의 파일 업로드 영역을 보면
- **THEN** 허용 미디어 타입과 자동 최적화가 적용됨을 안내하는 텍스트가 표시된다

#### Scenario: 미인증 유저는 업로드할 수 없다
- **WHEN** 미인증 상태에서 파일 업로드를 요청하면
- **THEN** 인증 오류가 반환된다

---

### Requirement: 파일 선택 시 타입을 즉시 검증한다
시스템은 파일 선택 시점에 허용된 MIME 타입인지 클라이언트에서 즉시 검증해야 한다(SHALL). 허용 타입: image/jpeg, image/png, image/gif, image/webp, audio/mpeg, audio/wav, audio/ogg, audio/flac, video/mp4, video/webm.

#### Scenario: 허용된 파일 타입 선택
- **WHEN** 사용자가 허용 목록에 포함된 MIME 타입의 파일을 선택하면
- **THEN** 검증을 통과하고 최적화 단계로 진행된다

#### Scenario: 허용되지 않은 파일 타입 선택
- **WHEN** 사용자가 허용 목록에 없는 MIME 타입의 파일을 선택하면
- **THEN** 에러가 즉시 표시되고 파일이 설정되지 않는다

---

### Requirement: 파일 선택 시 크기를 즉시 검증한다
시스템은 파일 선택 시점에 미디어 타입별 크기 제한을 클라이언트에서 즉시 검증해야 한다(SHALL). 최적화 전 원본 기준으로 서버 제한보다 여유 있게 허용한다.

#### Scenario: 허용 크기 이내의 파일 선택
- **WHEN** 사용자가 미디어 타입별 클라이언트 크기 제한 이내의 파일을 선택하면
- **THEN** 검증을 통과하고 최적화 단계로 진행된다

#### Scenario: 허용 크기 초과 파일 선택
- **WHEN** 사용자가 미디어 타입별 클라이언트 크기 제한을 초과하는 파일을 선택하면
- **THEN** 크기 초과 에러가 즉시 표시된다

---

### Requirement: 이미지를 웹 표준 크기로 압축한다
시스템은 이미지 파일 선택 시 클라이언트에서 자동으로 리사이즈 및 압축해야 한다(SHALL). GIF는 애니메이션 보존을 위해 압축하지 않는다(SHALL).

#### Scenario: 대형 이미지 자동 리사이즈
- **WHEN** 사용자가 웹 표준 크기를 초과하는 이미지를 선택하면
- **THEN** 비율이 유지된 채 리사이즈 및 압축된 이미지가 설정된다

#### Scenario: 이미 작은 이미지는 패스
- **WHEN** 사용자가 기준 크기 이하이고 기준 용량 이하인 이미지를 선택하면
- **THEN** 압축 없이 원본 그대로 설정된다

#### Scenario: GIF 애니메이션 보존
- **WHEN** 사용자가 GIF 파일을 선택하면
- **THEN** 압축 없이 원본 GIF가 그대로 설정된다

---

### Requirement: 오디오를 웹 재생에 적합한 형태로 정규화한다
시스템은 무압축/무손실 오디오(WAV, FLAC)를 웹 재생에 적합한 압축 포맷으로 변환하여 파일 크기를 줄여야 한다(SHALL). 이미 웹 재생 가능한 압축 포맷(MP3, OGG)은 변환 없이 유지한다(SHALL).

#### Scenario: MP3/OGG 파일은 패스스루
- **WHEN** 사용자가 MP3 또는 OGG 파일을 선택하면
- **THEN** 변환 없이 원본 그대로 설정된다

#### Scenario: 서버 크기 제한 초과 MP3/OGG
- **WHEN** 사용자가 서버 크기 제한을 초과하는 MP3 또는 OGG 파일을 선택하면
- **THEN** 크기 초과 에러가 즉시 표시된다

#### Scenario: WAV/FLAC에서 압축 포맷으로 변환
- **WHEN** 사용자가 WAV 또는 FLAC 파일을 선택하면
- **THEN** 웹 재생에 적합한 품질의 압축 포맷으로 변환된 파일이 설정된다

#### Scenario: 변환 후 크기 초과
- **WHEN** 오디오 변환 결과가 서버 크기 제한을 초과하면
- **THEN** 크기 초과 에러가 표시된다

#### Scenario: 브라우저가 오디오 변환을 지원하지 않는 경우
- **WHEN** 브라우저가 클라이언트 오디오 변환 기능을 지원하지 않으면
- **THEN** 최적화를 건너뛰고 원본 파일이 그대로 설정된다 (서버 크기 제한은 여전히 적용)

---

### Requirement: 비디오를 웹 표준으로 처리한다
시스템은 비디오 업로드 시 서버에서 웹 표준(H.264 1080p MP4)으로 처리해야 한다(SHALL). 클라이언트는 원본 비디오를 전송하고 서버에서 트리밍과 압축을 수행한다(SHALL).

#### Scenario: 고해상도 비디오 다운스케일
- **WHEN** 사용자가 1080p 초과 해상도의 비디오를 업로드하면
- **THEN** 서버가 1080p 이하로 다운스케일하여 저장한다

#### Scenario: 비표준 코덱 비디오 변환
- **WHEN** 사용자가 H.264/MP4가 아닌 비디오를 업로드하면
- **THEN** 서버가 H.264/MP4로 변환하여 저장한다

#### Scenario: 최적 조건 충족 비디오는 트리밍만 적용
- **WHEN** 사용자가 1080p 이하 H.264/MP4이며 서버 크기 제한 이하인 비디오를 업로드하고 트리밍 구간이 지정되면
- **THEN** 서버가 해당 구간을 트리밍하여 저장한다

#### Scenario: 최적 조건 충족 비디오는 변환 없이 저장
- **WHEN** 사용자가 1080p 이하 H.264/MP4이며 서버 크기 제한 이하이고 15초 이하인 비디오를 트리밍 구간 정보 없이 업로드하면
- **THEN** 서버가 변환 없이 원본을 그대로 저장한다

#### Scenario: 크기 초과 비디오 재압축
- **WHEN** 업로드된 비디오가 서버 크기 제한을 초과하면
- **THEN** 서버가 원본 해상도를 유지한 채 재인코딩하여 크기를 줄인다

#### Scenario: 재압축 후에도 크기 초과
- **WHEN** 재인코딩 후에도 비디오가 서버 크기 제한을 초과하면
- **THEN** 크기 초과 에러가 반환된다

---

### Requirement: 비디오 업로드 시 트리밍 구간 선택 모달을 표시한다
시스템은 15초 초과 비디오가 선택되면 트리밍 구간 선택 모달을 표시해야 한다(SHALL). 15초 이하 비디오는 모달 없이 바로 사용한다(SHALL).

#### Scenario: 15초 초과 비디오 선택 시 트리밍 모달 표시
- **WHEN** 사용자가 15초 초과 비디오를 선택하면
- **THEN** 비디오 프리뷰와 구간 선택 슬라이더가 포함된 모달이 표시된다

#### Scenario: 15초 이하 비디오 선택 시 모달 건너뛰기
- **WHEN** 사용자가 15초 이하 비디오를 선택하면
- **THEN** 트리밍 모달 없이 전체 비디오가 폼에 설정된다

#### Scenario: 비디오 프리뷰에서 선택 구간 확인
- **WHEN** 사용자가 슬라이더로 시작/종료 지점을 조정하면
- **THEN** 비디오 프리뷰가 선택된 시작 지점의 프레임을 표시한다

#### Scenario: 비디오 duration 감지 실패
- **WHEN** 클라이언트에서 비디오 duration을 감지할 수 없으면
- **THEN** 지원하지 않는 비디오 형식 에러를 표시하고 파일 선택을 초기화한다

---

### Requirement: 트리밍 구간은 최대 15초로 제한한다
시스템은 선택 가능한 구간의 길이를 최대 15초로 제한해야 한다(SHALL).

#### Scenario: 15초 이내 구간 선택
- **WHEN** 사용자가 15초 이내의 구간을 선택하면
- **THEN** 선택이 허용되고 선택된 구간의 길이가 표시된다

#### Scenario: 15초 초과 구간 선택 방지
- **WHEN** 사용자가 슬라이더를 15초 초과 구간으로 확장하려 하면
- **THEN** 슬라이더가 15초 지점에서 제한되어 더 이상 확장되지 않는다

---

### Requirement: 트리밍 확인 시 구간 정보를 폼에 전달한다
시스템은 트리밍 모달에서 확인 시 선택된 구간 정보를 핀 생성 폼에 전달해야 한다(SHALL). 폼에 표시되는 트림 요약은 트리밍 모달이 사용한 것과 동일한 시간 표기로 구간을 표시해야 한다(SHALL).

#### Scenario: 트리밍 확인
- **WHEN** 사용자가 트리밍 모달에서 확인 버튼을 클릭하면
- **THEN** 선택된 시작/종료 시간이 폼 데이터에 포함되고 모달이 닫힌다

#### Scenario: 트리밍 취소
- **WHEN** 사용자가 트리밍 모달에서 취소 버튼을 클릭하면
- **THEN** 비디오 선택이 취소되고 파일이 초기화된다

#### Scenario: 트림 요약 표기 일관
- **WHEN** 트리밍 확인 후 핀 생성 폼이 선택 구간 요약을 표시하면
- **THEN** 시작/종료 시각은 트리밍 모달의 판독과 동일한 분:초 표기로, 구간 길이는 모달과 동일한 초 단위 표기로 표시되며, 한 요약 안에서 서로 다른 시간 단위 표기가 혼용되지 않는다

### Requirement: 서버에서 비디오를 트리밍한다
시스템은 서버에서 전달받은 구간 정보를 기반으로 비디오를 트리밍해야 한다(SHALL). 트리밍된 결과는 웹 재생 가능한 비디오 형식으로 저장된다(SHALL).

#### Scenario: 구간 정보가 포함된 비디오 업로드
- **WHEN** 트리밍 구간 정보와 함께 비디오가 업로드되면
- **THEN** 서버가 해당 구간만 추출하여 저장한다

#### Scenario: 구간 정보 없이 15초 이하 비디오 업로드
- **WHEN** 트리밍 구간 정보 없이 15초 이하 비디오가 업로드되면
- **THEN** 서버가 전체 비디오를 사용한다

#### Scenario: 구간 정보 없이 15초 초과 비디오 업로드
- **WHEN** 트리밍 구간 정보 없이 15초 초과 비디오가 업로드되면
- **THEN** 서버가 업로드를 거부하고 트리밍 필요 에러를 반환한다

#### Scenario: 구간 정보 없이 비디오 길이를 확인할 수 없는 경우
- **WHEN** 트리밍 구간 정보 없이 비디오가 업로드되었으나 서버가 결정적으로 길이를 확인할 수 없는 경우
- **THEN** 서버가 업로드를 거부하고 길이 확인 불가 에러를 반환한다 (15초 초과 거부 SHALL이 길이 측정 실패라는 우연으로 침묵 우회되지 않도록 fail-closed)

#### Scenario: 트리밍 결과가 요청 구간과 크게 다른 경우
- **WHEN** 트리밍 결과의 길이가 요청된 구간과 크게 다르면
- **THEN** 서버가 정밀 트리밍을 수행하여 요청 구간에 가까운 결과를 반환한다

#### Scenario: 트리밍 실패 시 에러 반환
- **WHEN** 서버에서 트리밍이 실패하면
- **THEN** 에러 메시지가 반환된다

#### Scenario: 트리밍 결과가 서버 크기 제한을 초과하는 경우
- **WHEN** 트리밍 후에도 비디오가 서버 크기 제한을 초과하면
- **THEN** 서버가 재인코딩하여 크기를 줄인다

### Requirement: 최적화 진행 상황을 표시한다

### Requirement: MIME 타입 위조 방지는 storage 레이어에서 declared와 sniff의 불일치 거부로 enforce된다

핀 미디어 업로드 시 호출자가 storage 레이어에 전달하는 declared `Content-Type`과 서버가 첫 바이트 시퀀스로 sniff한 detected MIME이 모두 빈 문자열이 아니라면, 두 값이 정규화 후 일치해야 한다(SHALL). 불일치 시 storage 레이어는 업로드를 거부하고 에러 메시지에 `"unsupported file type"` 접두를 포함시켜 반환해야 한다(SHALL). 빈 declared `Content-Type`인 경우에는 비교를 수행하지 않고 sniff된 값으로만 허용 목록을 검증해야 한다(SHALL).

거부 시점은 storage가 외부 저장소(S3 등)에 객체를 쓰기 전이어야 한다(SHALL). 거부 에러는 핸들러의 기존 응답 매핑(`"unsupported file type"` 부분 일치 → 400 + "지원하지 않는 파일 형식입니다")으로 흘러야 한다(SHALL).

본 Requirement는 기존 Requirement `미디어 타입을 자동 감지한다`의 Scenario `MIME 타입 위조 방지`가 production에서 enforce되도록 보장하는 wiring 계약이다. 기존 Scenario의 행위 정의(불일치 시 유효성 검사 오류)는 변경하지 않는다.

#### Scenario: declared와 sniff가 일치하면 통과

- **WHEN** 인증된 유저가 PNG 파일을 `Content-Type: image/png`로 업로드하면
- **THEN** storage는 declared와 sniff가 일치함을 확인하고 업로드를 허용한다

#### Scenario: declared와 sniff가 정규화 후 같으면 통과

- **WHEN** 클라이언트가 JPEG 파일을 alias 표기(`image/jpg`, `image/pjpeg`) 또는 WAV를 `audio/x-wav`·`audio/wave`, MP3를 `audio/mp3`, FLAC를 `audio/x-flac`로 업로드하면
- **THEN** storage는 alias를 canonical 표기로 정규화한 뒤 sniff 결과와 비교하여 업로드를 허용한다

#### Scenario: declared가 비어 있으면 비교 미실행

- **WHEN** multipart 클라이언트가 part-level `Content-Type` 헤더를 표기하지 않고 업로드하면
- **THEN** storage는 declared·sniff 비교를 수행하지 않고 sniff된 MIME만으로 허용 목록을 검증한다

#### Scenario: declared와 sniff가 불일치하면 거부

- **WHEN** 클라이언트가 실제로는 WebM 비디오 바이트를 담은 파일을 `Content-Type: image/png`로 표기하여 업로드하면
- **THEN** storage는 declared(`image/png`)와 sniff(`video/webm`)의 불일치를 감지하여 `"unsupported file type"` 접두를 포함한 에러를 반환하고 외부 저장소에 객체를 쓰지 않으며, 핸들러는 400 + "지원하지 않는 파일 형식입니다"를 응답한다

#### Scenario: declared가 declared 카테고리는 같지만 정확한 MIME이 다르면 거부

- **WHEN** 클라이언트가 PNG 바이트를 `Content-Type: image/jpeg`로 표기하여 업로드하면
- **THEN** storage는 두 값이 모두 image 카테고리임에도 정확한 MIME이 다름을 이유로 거부하고 `"unsupported file type"` 접두를 포함한 에러를 반환한다


### Requirement: 핀 생성 폼 제출 버튼 라벨은 서비스 공통 제출 CTA 명사형 관례를 따른다

핀 생성 폼의 제출 버튼 유휴 라벨은 명사형("등록")으로 표기하며(SHALL), 제출 진행 중 라벨은 동일 어간의 진행형("등록 중...")을 유지한다(SHALL).

#### Scenario: 유휴 상태 제출 버튼 라벨

- WHEN 사용자가 핀 생성 화면에 진입하고 제출이 진행 중이 아닐 때
- THEN 제출 버튼 라벨은 "등록"으로 표시된다

#### Scenario: 제출 진행 중 라벨 유지

- WHEN 사용자가 제출 버튼을 눌러 제출이 진행 중일 때
- THEN 제출 버튼 라벨은 "등록 중..."으로 표시되고 버튼은 비활성화 및 busy 상태로 노출된다

### Requirement: 핀 생성 진입 트리거의 추가 기호는 장식 처리된다

내비게이션의 핀 생성 진입 트리거는 추가(add)를 나타내는 기호를 시각적으로 표시하되, 그 기호는 보조기술에 노출되는 접근 가능한 이름(accessible name)에 포함되지 않아야 한다(SHALL). 접근 가능한 이름은 동작 명칭("핀 생성")만으로 구성되어야 한다(SHALL).

#### Scenario: 스크린리더가 핀 생성 트리거를 읽는다

- WHEN 보조기술 사용자가 내비게이션의 핀 생성 진입 트리거에 도달하면
- THEN 트리거의 접근 가능한 이름은 "핀 생성"으로 발화되며 추가 기호("플러스" 등)는 발화되지 않는다

#### Scenario: 시각 사용자가 핀 생성 트리거를 본다

- WHEN 로그인 사용자가 내비게이션을 보면
- THEN 핀 생성 진입 트리거에 추가 기호와 "핀 생성" 라벨이 함께 표시된다

### Requirement: 핀 상세 이미지 미디어 로드 실패 시 깨진 이미지 표시를 노출하지 않는다

핀 상세 화면의 이미지 미디어가 로드에 실패하면(원본 URL 만료·삭제 등), 화면은 브라우저의 깨진 이미지 아이콘을 노출하지 않고 해당 이미지를 숨겨야 한다(SHALL). 제목·설명·크리에이터 등 나머지 상세 정보는 그대로 표시된다.

#### Scenario: 핀 상세 이미지 로드 실패

- **WHEN** 이미지 타입 핀의 상세 화면에서 미디어 URL이 로드에 실패하면
- **THEN** 깨진 이미지 아이콘 없이 미디어 영역이 숨겨지고, 제목·설명·크리에이터 정보는 정상 표시된다

#### Scenario: 정상 URL 렌더 불변

- **WHEN** 핀 상세 이미지 미디어가 정상적으로 로드되면
- **THEN** 기존과 동일한 레이아웃으로 미디어가 표시된다
