## Purpose

유저의 핀/조회 이력에 기반한 개인화 추천 피드와 작품 상세에서의 연관 작품 목록을 제공한다.
## Requirements
### Requirement: 개인화된 추천 피드를 제공한다
시스템은 유저의 핀/조회 행동 기반으로 개인화된 작품 피드를 제공해야 한다(SHALL). 추천은 태그 빈도와 미디어 타입 선호도를 기반으로 한다.

#### Scenario: 충분한 핀이 있는 유저
- **WHEN** 10개 이상의 핀을 가진 유저가 피드를 요청하면
- **THEN** 유저의 태그 선호도와 미디어 타입 선호도를 반영한 추천 작품과 최신 작품이 혼합되어 반환된다

#### Scenario: 핀이 부족한 유저 (콜드 스타트)
- **WHEN** 10개 미만의 핀을 가진 유저가 피드를 요청하면
- **THEN** 최신순으로 작품이 반환된다

#### Scenario: 비인증 유저
- **WHEN** 비인증 상태에서 피드를 요청하면
- **THEN** 최신순으로 작품이 반환된다

#### Scenario: 이미 핀한 작품은 추천에서 제외
- **WHEN** 유저가 이미 핀한 작품이 추천 후보에 포함되면
- **THEN** 해당 작품은 피드에서 제외된다

#### Scenario: 피드 페이지네이션
- **WHEN** 피드의 다음 페이지를 요청하면
- **THEN** 이전 페이지에 포함되지 않은 작품이 반환된다

---

### Requirement: 연관 작품을 제공한다
시스템은 작품 상세 페이지에서 유사한 작품 목록을 제공해야 한다(SHALL). 태그 일치도와 미디어 타입을 기준으로 연관성을 판단한다.

#### Scenario: 태그가 겹치는 연관 작품
- **WHEN** 특정 작품의 연관 작품을 요청하면
- **THEN** 태그가 겹치는 작품이 일치도 순으로 반환된다

#### Scenario: 동일 미디어 타입 우선
- **WHEN** 연관 작품이 여러 미디어 타입에 걸쳐 있으면
- **THEN** 같은 미디어 타입의 작품이 우선적으로 표시된다

#### Scenario: 자기 자신 제외
- **WHEN** 연관 작품을 조회하면
- **THEN** 조회 대상 작품 자체는 결과에 포함되지 않는다

#### Scenario: 최대 개수 제한
- **WHEN** 연관 작품을 조회하면
- **THEN** 최대 10개까지 반환된다

### Requirement: 피드 라우트는 선택적 인증 미들웨어로 보호된다

production 서버 라우터의 피드 엔드포인트는 선택적 인증 미들웨어를 통해 핸들러에 도달해야 한다(SHALL). 인증 토큰이 존재하면 그 토큰의 유저 식별자가 핸들러에 노출되어야 한다(SHALL). 토큰이 부재하거나 유효하지 않으면 핸들러가 비인증 호출자에 대한 분기를 수행하도록 빈 인증 컨텍스트로 진입해야 한다(SHALL). 피드 라우트가 토큰 부재만으로 401을 반환해서는 안 된다(SHALL NOT).

본 Requirement는 기존 Requirement `개인화된 추천 피드를 제공한다`가 production에서 enforce되도록 보장하는 wiring 계약이다. 기존 Requirement의 행위 정의(보유 핀 수에 따른 개인화·콜드스타트·비인증 분기)는 변경하지 않는다.

#### Scenario: 인증 토큰을 가진 피드 요청

- **WHEN** 인증 토큰을 제시한 호출자가 피드를 요청하면
- **THEN** 핸들러는 호출자의 유저 식별자로 분기 가능한 상태에서 호출되어, 기존 Requirement `개인화된 추천 피드를 제공한다`의 "충분한 핀이 있는 유저"·"핀이 부족한 유저(콜드 스타트)" Scenario에 정의된 응답을 반환한다

#### Scenario: 인증 토큰 없는 피드 요청

- **WHEN** 인증 토큰이 없는 호출자가 피드를 요청하면
- **THEN** 핸들러는 비인증 분기를 수행하며, 기존 Requirement `개인화된 추천 피드를 제공한다`의 "비인증 유저" Scenario에 정의된 응답을 반환한다. 401은 반환되지 않는다

#### Scenario: 유효하지 않은 토큰을 가진 피드 요청

- **WHEN** 만료·서명 불일치·식별자 파싱 실패 중 어느 사유로든 유효하지 않은 토큰을 제시한 호출자가 피드를 요청하면
- **THEN** 핸들러는 비인증 분기를 수행하며, "비인증 유저" Scenario에 정의된 응답을 반환한다. 401은 반환되지 않는다

### Requirement: 개인화 피드의 페이지네이션은 페이지 간 작품 중복을 반환하지 않는다

시스템은 개인화 피드(authenticated 호출자 + 보유 핀 수가 콜드스타트 임계 이상) 분기에서 응답된 `next_cursor`를 그대로 다음 요청에 전달했을 때, 다음 페이지의 응답이 이전 페이지에 포함되었던 작품을 포함해서는 안 된다(SHALL NOT). 즉 연속한 두 페이지 응답의 작품 식별자 교집합은 비어 있어야 한다(SHALL).

개인화 분기는 추천 후보(태그 매칭·미디어 타입 매칭)와 최신 작품 보충 두 종류의 소스에서 작품을 모아 응답을 만든다. cursor가 표현하는 페이지 위치(offset)는 응답을 만들 때 사용되는 모든 underlying 쿼리에 일관되게 전파되어야 한다(SHALL). 어떤 underlying 쿼리도 페이지 위치를 무시한 채 첫 페이지의 결과를 그대로 다시 만들어내서는 안 된다(SHALL NOT).

본 Requirement는 기존 Requirement `개인화된 추천 피드를 제공한다` Scenario "피드 페이지네이션"의 SHALL("이전 페이지에 포함되지 않은 작품이 반환된다")이 production에서 enforce되도록 보장하는 wiring 계약이다. 기존 Scenario의 의미와 cold-start/비인증 분기의 동작은 변경하지 않는다.

#### Scenario: 연속한 두 페이지의 작품 ID 교집합은 비어 있다

- **WHEN** 보유 핀 수가 콜드스타트 임계 이상인 인증된 호출자가 첫 페이지 피드를 요청하고, 응답의 `next_cursor`를 그대로 두 번째 요청의 cursor로 전달하면
- **THEN** 두 응답의 `pins[].id` 집합은 disjoint이다. 같은 작품이 두 페이지에 모두 등장해서는 안 된다

#### Scenario: 페이지 offset이 모든 underlying 소스에 일관되게 적용된다

- **WHEN** 개인화 분기로 두 번째 페이지가 만들어지면
- **THEN** 응답 페이로드를 구성하는 모든 underlying 쿼리(태그 기반 추천·미디어 타입 기반 추천·최신 작품 보충 등 응답을 만드는 데 사용되는 모든 소스)는 첫 페이지가 소비한 위치 다음에서부터 작품을 가져온다. 어떤 소스도 첫 페이지와 동일한 결과를 반환하지 않는다

#### Scenario: cold-start와 비인증 분기에는 추가 제약을 부과하지 않는다

- **WHEN** 보유 핀 수가 콜드스타트 임계 미만인 인증된 호출자 또는 비인증 호출자가 페이지 피드를 요청하면
- **THEN** 응답은 기존 Requirement `개인화된 추천 피드를 제공한다`의 "핀이 부족한 유저(콜드 스타트)"·"비인증 유저" Scenario가 정의한 동작을 따른다. 본 Requirement는 이들 분기에 대해 추가 제약을 부과하지 않는다


### Requirement: 피드 빈 상태 메시지는 서비스 공통 카피 어체를 따른다

피드의 분야 필터 결과가 비어 있을 때 표시되는 빈 상태 메시지는 서비스 전반의 문장형 안내 카피와 동일한 격식 어체(합쇼체, "-습니다" 종결)로 작성되어야 한다(SHALL). 같은 빈 상태 역할을 하는 다른 표면(프로필 작품 없음, 보드 없음)의 메시지와 어체가 갈리지 않아야 한다(SHALL NOT).

#### Scenario: 분야 필터 빈 결과의 어체

- **WHEN** 사용자가 작품이 없는 분야 필터를 선택해 빈 상태가 표시되면
- **THEN** 빈 상태 메시지는 "이 분야의 작품이 아직 없습니다"로, 격식 어체(합쇼체)로 렌더된다

#### Scenario: 빈 상태 표면 간 어체 일관

- **WHEN** 피드·프로필·보드의 빈 상태 메시지를 비교하면
- **THEN** 모든 빈 상태 메시지가 동일한 격식 어체(합쇼체)로 종결되며, 특정 표면만 비격식 어체(해요체)로 갈리지 않는다
