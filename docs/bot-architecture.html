URLScheduler PGURLScheduler (Postgres)

두 워커의 유일한 작업 경계. FOR UPDATE SKIP LOCKED 로 N-워커 동시성 보장.

  • 테이블: pioneer_frontier / harvester_frontier / harvester_frontier_pins
  • 키: url_hash = sha256(canonical(url))
  • 10분 리스 · 1초 빈큐 폴링
  • HostRateLimiter.Allow(host) 호스트 정중성 체크
  • 실패 4종 (http_4xx/http_5xx/network/timeout) → backoff (5단계, jitter)
  • http_4xx 는 즉시 dead (count=5)
  • SetStatus(harvested, pinIDs) 는 동일 트랜잭션에서 harvester_frontier_pins 벌크 INSERT
Enqueue / EnqueueHarvester / Dequeue / SetStatus / RecordFetchError / RecordHarvestError

Harvester HarvesterConsumer.Run

수확 워커. 사이트 스코프 인메모리 상태 없음. 1 URL → 1 PinDocument → 1 Pin.

  • Dequeue(QueueHarvester)
  • SnapshotFirstFetch.Fetch (ObjectStorage → HTTP fallback)
  • AdapterRegistry (도메인별) → 실패 시 GenericExtractor 폴백 (AdapterFallback++)
  • MediaValidator.FilterValidMedia
  • Classifier.Classify → listing/empty_body/no_primary_media
  • DocumentPipeline.ProcessDocument → Upsert on canonical URL
  • SetStatus(harvested, pinIDs) / 실패 시 SetStatus(harvest_failed) + RecordHarvestError(kind)
stats: PinsCreated / Deduped / Skipped / Failed / AdapterFallback harvesterDequeueBudget = 100
Storage layer

SnapshotStore ObjectStorage

Pioneer 가 쓰고 Harvester 가 읽는 공유 스냅샷 저장소. 키는 snapshot.SnapshotKey(canonical, now).

  • Pioneer 단계에서 원본 HTML 그대로 저장 → 재현 가능한 추출
  • Harvester 의 1차 fetch 경로. miss/네트워크/권한 실패는 모두 HTTP fallback 으로 흡수
  • 스냅샷 키는 EnqueueHarvester(url, snapshotKey) 로 frontier 행에 함께 기록

Pins DB Postgres

봇 Pin 의 정규형 저장소. canonical URL 단위 upsert.

  • pins_url_bot_unique partial unique index
  • creator_id = bot UUID 술어 IMMUTABLE 매칭
  • xmax=0 → PinsCreated, 아니면 Deduped

파이프라인 한 줄 요약 — Pioneer 가 사이트를 탐색하며 HTML 스냅샷을 남기고 발견 링크와 함께 harvester_frontier 에 적재한다. URLScheduler 가 두 큐의 dedup·순서·리스·백오프·호스트 레이트리밋을 단독 소유한다. Harvester 는 스냅샷을 먼저 읽어 추출·분류·검증을 거쳐 Pin 으로 영속화한다. 두 워커 모두 100 URL = 1 프로세스 정책이며 외부 슈퍼바이저가 재시작을 책임진다.
