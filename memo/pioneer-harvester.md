내가 실제로 현재 구현된 Pioneer와 Harvester 를 pixiv대상으로 써봤는데 다음 결과가 나옴

  잘된점.
  1. 중복노드 제거하여 사이트맵 구성

  못된점.
  1. Pioneer가 생성한 스크립트 수율이 매우 나쁨. 정확도에 문제가 있어보임.
  2. 그닥 중요한 건 아니긴 한데 Pioneer동작이 오래걸림.

  우리가 개선해야할 점은 1번. 정확도와 수율.
  하지만 현재 LLM에게 스크립트를 직접 생성하는 방식으로는 정확도를 높이는 데 한계가 있음. 무엇보다 정확도 측정이 객관적 지표가 아닌 사람 직관에
  의해 이뤄지고 있는 중.

  다음과 같은 구조적 개선을 해보려고 함.

  핵심: LLM으로 스크립트 생성은 하지 않는다. 파싱할 때 ML을 사용한다.
  Harvestor의 역할: HTML에서 컨텐츠를 추출한다. 이 때 ML을 사용한다.
  주의점: 사이트가 SPA혹은 동적 자바스크립트 렌더링인 경우 최종 컨텐츠를 HTML을 단순 요청으로 얻을 수 없다.

  ## Harvester
  1. 최종 HTML을 얻는다.
  2. ML 모델을 통해 "컨텐츠(title, url, image 등)" 을 가지는 컨텐츠를 추출한다.

  ML 모델은 직접 생성한다.
  Andrej Karpathy의 autoresearch 프레임워크를 빌려, Claude Code가 스스로 가설을 세우고 실험을 반복하는 방식으로 광고 매칭 ML 모델을 만든다.
