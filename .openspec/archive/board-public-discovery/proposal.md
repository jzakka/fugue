# Proposal: 타인의 보드 공개 탐색 경로 확보

## 문제

현재 보드는 `/mypage`에서만 본인 보드를 볼 수 있다. 타인의 보드에 접근할 수 있는 진입점이 전혀 없다:

1. 크리에이터 프로필(`/creators/{id}`)에 보드 섹션이 없어 타인의 큐레이션 보드를 발견할 수 없다
2. 보드 상세 API(`GET /api/boards/{id}`)가 보드 메타데이터만 반환하고 소속 핀 목록을 포함하지 않아 보드 상세 페이지가 빈 상태로 렌더링된다
3. 핀 상세 페이지에서 해당 핀이 어떤 보드에 소속되어 있는지 알 수 없어 보드 탐색 경로가 끊긴다

## 해결 방향

### 1. 크리에이터 프로필에 보드 섹션 추가

크리에이터 프로필 페이지(`/creators/{id}`)에 해당 크리에이터의 공개 보드 목록을 표시한다. 기존 `/mypage`의 보드 섹션과 동일한 카드 형태로 보여주되, 보드 생성/편집 기능은 노출하지 않는다(읽기 전용).

### 2. 보드 상세 API에 핀 목록 포함

`GET /api/boards/{id}` 응답에 보드 메타데이터와 함께 소속 핀 목록을 포함한다. DB에 이미 존재하는 보드 소속 핀 조회 쿼리를 활용하여 페이지네이션된 핀 목록을 반환한다. 프론트엔드가 기대하는 `{ board, pins, has_more }` 형태의 응답을 생성한다.

### 3. 핀 상세에 소속 보드 링크 추가

핀 상세 페이지(`/pins/{id}`)에 해당 핀이 소속된 공개 보드 목록을 표시한다. 각 보드는 보드 상세 페이지로 연결되는 링크로 제공한다. 이를 위해 핀 ID로 소속 보드를 조회하는 API를 추가한다.

## 영향 범위

- **Backend**: 보드 상세 핸들러 수정, 핀 소속 보드 조회 쿼리/API 추가
- **Frontend**: 크리에이터 프로필 페이지 보드 섹션, 핀 상세 보드 링크
- **DB**: 새 쿼리 추가 (핀 ID → 공개 보드 목록)
- **기존 기능 영향 없음**: 마이페이지, 보드 CRUD, 핀 CRUD는 변경 없음
